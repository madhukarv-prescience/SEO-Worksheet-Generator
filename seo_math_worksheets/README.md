# Bhanzu SEO Math Worksheets

A hosted tool: bring in source worksheets, generate new ones from them,
validate them automatically, review and edit in plain English, approve,
print. See `../ARCHITECTURE.md` for the full picture (including how this
connects to the K5 fetcher next door).

## Run it

```bash
cd "SEO_Worksheets/seo_math_worksheets"
pip3 install -r requirements.txt
python3 -m uvicorn app.main:app --port 8020
```

Then open **http://127.0.0.1:8020**

It runs with **no API key at all** — every screen works and worksheets
show clearly-labelled sample content, so the interface can be reviewed
before anyone spends money.

## Turn on real question writing

```bash
cp .env.example .env
```

Open `.env`, paste in **one** key, save, restart. The app detects which
provider you used — you don't tell it. Check the **Setup** tab in the
app to confirm what's active without opening the file again.

| Key | Where from | Notes |
|---|---|---|
| `GROQ_API_KEY` | console.groq.com/keys | Free tier. Fastest. Currently in use as the placeholder. |
| `ANTHROPIC_API_KEY` | console.anthropic.com | Paid. |
| `OPENAI_API_KEY` | platform.openai.com/api-keys | Paid. Also unlocks decorative image generation. |
| `CANVA_CLIENT_ID` / `_SECRET` / `_BRAND_TEMPLATE_ID` | canva.com/developers | Optional image fallback — needs **Canva Enterprise**, see below. |

If more than one key is set, the order is Groq → Anthropic → OpenAI.
Force a specific one with `LLM_PROVIDER=openai` (or `groq`/`anthropic`)
in `.env`.

## The flow

```
Library ──── Create ──── [validation gate] ──── Review & approve
   │            │                                     │
3 ways in:  grade (K–10),                    edit questions by hand,
collections, difficulty,               ask for a change in plain English,
Drive link,  build mode,                approve / reject, preview, print
upload      templates,
            closing message
```

Two standing reference views sit in the top bar, separate from that
workflow: **Repository** (every source ever brought in, and what's been
built from each) and **Approved** (everything signed off, ready to
download). **Setup** shows what's configured — see below.

Bulk runs ("use every worksheet in the library") happen on a background
job with a progress bar; Review fills in as each source finishes rather
than waiting for the whole run.

## The validation gate

Every generated worksheet passes through `app/validate.py` before it
reaches Review — this is not optional and cannot be skipped:

1. **Structural checks** (free, instant, deterministic): missing
   answers, blank template stems (`___ + ___ = ___`), duplicate
   questions, numbers outside the grade's range, a picture that reveals
   its own answer, a blank or missing diagram.
2. **Sense check** (one API call): does each question actually make
   sense, and is the stated answer arithmetically correct.

The result is one of four verdicts shown on every worksheet card:
**passed**, **images need redrawing** (fixed automatically — from the
free deterministic renderer first, Canva second if configured; questions
are never touched on this path), **needs another pass**, or **could not
finish checking** (never silently treated as a pass).

Sources that have no real question to mine at all (K5's "colour by
number" activity sheets — a colour key and an instruction to colour a
picture, nothing to regenerate) are flagged in the Library and excluded
from bulk runs by default, so a run doesn't spend API quota on results
that were never going to validate.

## How the pictures work — read this before asking for an image API

Worksheet diagrams (number lines, counters, ten-frames, arrays, bar
models) are **drawn by Python**, not generated by an image model.

The reason is not cost. An image model cannot be trusted to draw exactly
7 counters when the question says 7, or to put a tick at 24 on a number
line. It produces something that *looks* right and is arithmetically
wrong — and it renders "successfully", so only a human catches it. On a
maths worksheet that is the worst possible failure.

So the language model only supplies a **structured spec**
(`{"kind":"ten_frame","filled":7}`) and Python draws it. Always correct,
costs nothing, redraws identically forever.

An OpenAI key additionally enables `generate_realistic_image()` for
decorative/photo-real artwork. It is never used where the maths has to
be right.

**Canva** is optional and not required — and has a real catch: its
Autofill API needs a **Canva Enterprise** plan (Canva's own requirement,
stated in their docs — not something this app can work around). It's
also OAuth, not a static key: a real person clicks "Allow" once from the
**Setup** tab, after `CANVA_CLIENT_ID`/`CANVA_CLIENT_SECRET`/
`CANVA_BRAND_TEMPLATE_ID` are in `.env`. Full flow is implemented —
`app/providers/canva.py` — including the PKCE handshake, encrypted token
storage with auto-refresh, and the real async upload → autofill → export
job sequence. Without a completed connection, a picture that fails
validation is simply redrawn for free.

## What makes the worksheets different from each other

`app/framework.py` — the instructional design framework. This is what
stops the model just swapping apples for oranges and calling it a new
worksheet.

Six controllable dimensions:

| Dimension | What it does |
|---|---|
| Cognitive demand | How much thinking the question needs (recall → apply → reason) |
| Representation | Objects, pictures, or symbols — shifts with grade |
| Cognitive load | How many things a child holds in mind at once. The honest measure of difficulty. |
| Variation | Change ONE thing at a time. Varying everything teaches nothing. |
| Difficulty levers | Number size, step count, where the unknown sits, scaffolding |
| Worksheet arc | Warm up → Practice → Stretch → Reflect |

Grades run **Kindergarten through Grade 10**. Two build modes, pickable
together: **change the context** (same questions, new objects/names/
numbers) and **more questions of these types** (mine the source's
question types, write many more of each — for building a bank).

## Files

```
app/
  framework.py    the instructional design framework
  config.py       reads .env, picks the provider automatically, key_status()
  db.py           SQLite — whole schema visible in one screen
  ingest.py       the three ways a PDF gets in + source-quality flagging
  generate.py     source PDF -> N new worksheets
  validate.py     the validation gate
  jobs.py         background bulk-run tracking
  providers/
    llm.py        Groq / Anthropic / OpenAI / sample, one interface
    images.py     deterministic diagram drawing + OpenAI decorative art
    canva.py      image-only fallback — real OAuth+PKCE, needs Canva Enterprise
    drive.py      pushes approved worksheets to a shared team Drive folder
  export/
    worksheet_html.py   branded printable page + real PDF via Chrome
static/           the interface (plain JS, no build step)
data/             uploads, exports, diagrams, templates, studio.db
```

## Known limits

- **Google Drive folder links don't work** — only single-file links.
  Folder listing needs Drive API credentials. Open the folder, copy the
  individual PDF's link.
- **Large Drive files fail** — Drive serves a virus-scan warning page
  instead of the file. Download it and upload directly.
- **No login.** Don't put it on a public URL as-is — anyone who finds it
  can spend your API credits.
- **Templates are stored and selectable but don't yet drive the export's
  visual layout** — real templates are still being designed.
- **Publishing to the Bhanzu website isn't built yet.** That's the next
  piece, and it's waiting on how the team wants pages created.
- **Free-tier API limits are real.** Groq's free tier is roughly one
  worksheet per minute and ~28 per day (200,000 tokens/day ÷ ~7k tokens
  each) — the app paces itself against this automatically, but bulk
  generation across hundreds of sources needs a paid tier.

## Keep this separate from BLC

This is the SEO project. BLC Worksheets is a different project with
different content, different guidelines, and its own credentials. Never
copy a `.env` between them.
